# 個人反思日誌錯誤碼對照表

## 概述

為了統一前後端錯誤訊息，方便除錯和用戶體驗，我們建立了統一的錯誤碼系統。

### 檔案位置

- **後端**: `sdl-backend-main/constants/dailyErrorCodes.js`
- **前端**: `sdl-frontend-main/src/constants/dailyErrorCodes.js`

---

## 錯誤碼分類

### 1. 前端驗證錯誤 (400)

| 錯誤碼 | 英文訊息 | 中文訊息 | 觸發場景 |
|--------|---------|---------|----------|
| `EMPTY_TITLE` | Title is required | 請輸入標題 | 用戶未填寫標題 |
| `EMPTY_CONTENT` | Content is required | 請輸入內容 | 用戶未填寫內容 |
| `EMPTY_TITLE_AND_CONTENT` | Both title and content are required | 標題及內容請填寫完整 | 標題和內容都為空 |
| `INVALID_5RS_FORMAT` | 5Rs reflection data validation failed | 5Rs 反思格式驗證失敗 | 5Rs 資料結構錯誤 |
| `NO_DAILY_SELECTED` | No daily log selected for editing | 未選擇日誌 | 編輯時未選擇日誌 ID |
| `INVALID_5RS_CONTENT` | Unable to parse 5Rs reflection content | 無法解析 5Rs 反思內容 | 5Rs JSON 解析失敗 |
| `INSUFFICIENT_5RS_STEPS` | At least 3 sections must be completed for AI analysis | 請至少完成 3 個部分再請求 AI 分析 | 5Rs 完成度不足 3 個部分 |

## 使用方式

### 後端使用

```javascript
const { createErrorResponse } = require('../constants/dailyErrorCodes');

// 返回錯誤
if (!title) {
    const errorResponse = createErrorResponse('EMPTY_TITLE');
    return res.status(400).json(errorResponse);
}

// 返回格式
{
    success: false,
    errorCode: 'EMPTY_TITLE',
    message: 'Title is required',  // 英文訊息（開發者看）
    messageZh: '請輸入標題'         // 中文訊息（用戶看）
}
```

### 前端使用

```javascript
import { extractErrorMessage, DAILY_ERROR_CODES } from '@/constants/dailyErrorCodes.js';

// 方法 1: 使用 extractErrorMessage 自動提取
try {
    await createPersonalDaily(data);
} catch (error) {
    const errorMessage = extractErrorMessage(error);
    toast.error(errorMessage);  // 自動顯示中文
}

// 方法 2: 直接使用錯誤碼
if (!title || !content) {
    toast.error(DAILY_ERROR_CODES.EMPTY_TITLE_AND_CONTENT.zh);
}
```

## 除錯指南

### 1. 查看完整錯誤資訊

前端控制台會顯示：
```javascript
console.log('=== 錯誤訊息提取 ===');
console.log('錯誤對象:', error);
console.log('錯誤回應:', error.response);
console.log('錯誤資料:', error.response?.data);
console.log('errorCode:', errorCode);
console.log('message (en):', message);
console.log('messageZh:', messageZh);
```

後端控制台會顯示：
```javascript
console.error('❌ 創建個人日誌失敗:', err);
// 並返回結構化錯誤
```

### 2. 常見錯誤排查

#### 前端顯示 "發生未知錯誤"
- **原因**: 後端返回的錯誤碼不在對照表中，或網路完全斷開
- **排查**: 檢查後端 Console，確認返回的 `errorCode` 是否正確

#### 前端顯示英文錯誤訊息
- **原因**: 後端返回了舊格式（只有 `message` 沒有 `errorCode`）
- **排查**: 檢查是否更新了所有 Controller 的錯誤處理

#### Token 過期後無法操作
- **原因**: `validateToken` 中間件返回 401
- **解決**: 前端應導向登入頁面

## 維護注意事項

### 新增錯誤碼

1. **同時更新前後端對照表**
   - `sdl-backend-main/constants/dailyErrorCodes.js`
   - `sdl-frontend-main/src/constants/dailyErrorCodes.js`

2. **格式要求**
   ```javascript
   NEW_ERROR_CODE: {
       code: 'NEW_ERROR_CODE',  // 必須與 key 相同
       en: 'English message',
       zh: '中文訊息'
   }
   ```

3. **更新此文檔**
   - 將新錯誤碼加入對應分類
   - 說明觸發場景

### 向後相容

- `extractErrorMessage` 函數包含向後相容邏輯
- `mapLegacyErrorMessage` 可以映射舊的錯誤訊息
- 即使後端返回舊格式，前端也能正確顯示

## 完整錯誤流程圖

```
用戶操作
    ↓
前端驗證 (可選)
    ├─ 失敗 → toast.error(DAILY_ERROR_CODES.XXX.zh)
    ↓
發送 API 請求
    ↓
後端中間件層
    ├─ validateToken → 401 UNAUTHORIZED
    ├─ checkProjectViewingPermission → 403 INSUFFICIENT_PERMISSIONS
    ├─ checkWritePermission → 403 WRITE_PERMISSION_DENIED
    ├─ MinIO 上傳 → 400/500 FILE_XXX
    ↓
Controller 業務邏輯
    ├─ 驗證失敗 → 400 EMPTY_XXX
    ├─ 資源不存在 → 404 XXX_NOT_FOUND
    ├─ 資料庫錯誤 → 500 XXX_FAILED
    ↓
返回標準格式
    {
        success: false,
        errorCode: 'XXX',
        message: 'English',
        messageZh: '中文'
    }
    ↓
前端 extractErrorMessage() 解析
    ├─ 優先使用 messageZh
    ├─ 其次使用 errorCode 對照表
    ├─ 最後使用 message
    ↓
toast.error(中文訊息)
```

## 常見問題 FAQ

### Q1: 為什麼前端看到的是英文錯誤訊息？
**A**: 可能原因：
1. 後端返回了舊格式（沒有 `errorCode`）
2. 錯誤碼不在對照表中
3. 前端沒有正確引入 `extractErrorMessage`

### Q2: 如何確認錯誤碼是否生效？
**A**:
1. 打開瀏覽器開發者工具 → Network 標籤
2. 查看失敗的請求 → Response 標籤
3. 確認回應包含 `errorCode` 和 `messageZh`

### Q3: 舊的錯誤訊息會被覆蓋嗎？
**A**: 不會。`extractErrorMessage` 有向後相容邏輯，會嘗試映射舊訊息。

### Q4: 多語系支援？
**A**: 目前支援中英文。新增其他語言：
1. 在錯誤碼對照表中添加新語言欄位
2. 修改 `extractErrorMessage` 函數讀取對應語言
