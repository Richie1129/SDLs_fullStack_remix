# Test Case 測試案例設計

## 概述

此 skill 提供測試案例設計指引，確保測試案例完整、可重複執行、易於維護。

## 適用角色

| 角色 | 職責 |
|------|------|
| **主要負責** | QA 工程師 |
| **協作角色** | 產品經理、開發工程師 |

---

## 1. 測試案例元素

| 元素 | 說明 |
|------|------|
| **TC-ID** | 唯一識別碼 |
| **標題** | 清楚描述測試目標 |
| **前置條件** | 測試前必須滿足的條件 |
| **測試步驟** | 詳細操作步驟 |
| **預期結果** | 每步驟的預期結果 |
| **優先級** | P0/P1/P2/P3 |

---

## 2. 測試案例模板

```markdown
## TC-USER-001: 有效帳號登入成功

### 基本資訊
- **模組**: 用戶認證
- **優先級**: P0
- **類型**: 功能測試
- **自動化狀態**: ✅ 已自動化

### 前置條件
1. 用戶帳號已註冊（email: test@example.com）
2. 帳號狀態為「啟用」
3. 瀏覽器已清除快取

### 測試步驟

| 步驟 | 操作 | 預期結果 |
|------|------|----------|
| 1 | 開啟登入頁面 | 顯示登入表單 |
| 2 | 輸入 Email: test@example.com | Email 欄位顯示輸入值 |
| 3 | 輸入密碼: Password123! | 密碼以遮罩顯示 |
| 4 | 點擊「登入」按鈕 | 顯示載入中狀態 |
| 5 | 等待頁面跳轉 | 跳轉至儀表板頁面 |
| 6 | 驗證用戶資訊 | 顯示「歡迎 Test User」 |

### 測試資料
- Email: test@example.com
- Password: Password123!
```

---

## 3. 測試設計技術

### 3.1 等價類劃分

```
輸入：年齡 (1-120)

等價類：
├── 有效類：1-120 → 測試值: 1, 60, 120
├── 無效類 1：< 1 → 測試值: 0, -1
└── 無效類 2：> 120 → 測試值: 121, 999
```

### 3.2 邊界值分析

```
範圍：1-120

邊界測試點：
0 (下界-1)
1 (下界)
2 (下界+1)
119 (上界-1)
120 (上界)
121 (上界+1)
```

### 3.3 決策表

| 條件 | R1 | R2 | R3 | R4 |
|------|----|----|----|----|
| 會員 | Y | Y | N | N |
| 訂單 > 1000 | Y | N | Y | N |
| **動作** | | | | |
| 9 折 | ✓ | | | |
| 95 折 | | ✓ | | |
| 原價 | | | ✓ | ✓ |

## 4. 測試優先級

| 優先級 | 定義 | 執行頻率 |
|--------|------|---------|
| **P0** | 核心功能、阻斷性 | 每次發布 |
| **P1** | 主要功能 | 每次發布 |
| **P2** | 次要功能 | 每週回歸 |
| **P3** | 邊緣場景 | 每月回歸 |

---

## 5. 測試案例管理

### 組織結構

```
測試案例
├── 用戶管理
│   ├── 註冊
│   │   ├── TC-REG-001: 有效資料註冊
│   │   ├── TC-REG-002: Email 重複
│   │   └── TC-REG-003: 密碼強度不足
│   ├── 登入
│   └── 登出
├── 訂單管理
│   ├── 創建訂單
│   └── 取消訂單
└── 支付
```

### 追溯矩陣

| 需求 ID | 測試案例 |
|---------|---------|
| REQ-001 | TC-REG-001, TC-REG-002 |
| REQ-002 | TC-LOGIN-001, TC-LOGIN-002 |
| REQ-003 | TC-ORDER-001 ~ TC-ORDER-005 |
