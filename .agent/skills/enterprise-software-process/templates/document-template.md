# 文件模板

## 概述
此 skill 提供標準化的文件模板，確保專案中所有文件遵循一致的結構、格式和品質標準。適用於建立各類技術文件、規劃文件和報告。

## 適用角色
- **主要負責**: 所有需要撰寫文件的角色
- **協作角色**: 文件審核者、專案經理

## 輸入需求
使用者需要提供：
- 文件類型 (技術規格、設計文件、報告等)
- 文件目的和受眾
- 核心內容要點 (可選)

範例：`請幫我建立一份 [文件類型] 文件，目的是 [說明目的]，受眾是 [目標讀者]`

## 執行步驟

### 步驟 1: 確認文件需求
- 詢問使用者文件類型和目的
- 確認目標受眾和詳細程度
- 了解文件使用場景

### 步驟 2: 選擇適當模板
根據文件類型選擇對應的結構模板：
- 技術文件：背景、架構、實作、維護
- 規劃文件：目標、範圍、時程、資源
- 報告文件：摘要、發現、分析、建議

### 步驟 3: 生成文件框架
依據模板建立完整的文件大綱，包含所有必要章節。

### 步驟 4: 填充內容指引
在每個章節提供撰寫指引和範例，協助使用者完成內容。

### 步驟 5: 添加品質檢查清單
在文件末尾加入檢查清單，確保文件完整性。

## 範例

### 輸入範例
```
請幫我建立一份 API 設計文件，目的是記錄使用者認證 API 的規格，
受眾是後端開發團隊和前端整合團隊。
```

### 輸出範例
```markdown
# 使用者認證 API 設計文件

**版本**: 1.0
**日期**: 2026-01-18
**作者**: 後端架構師
**審核者**: 技術主管
**狀態**: 審核中

## 1. 概述

### 1.1 文件目的
本文件定義使用者認證 API 的技術規格，包括端點定義、請求/回應格式、
錯誤處理和安全要求。

### 1.2 目標受眾
- 後端開發工程師（實作 API）
- 前端開發工程師（整合 API）
- QA 工程師（測試 API）
- DevOps 工程師（部署和監控）

### 1.3 範圍
**包含**: 使用者註冊、登入、登出、Token 刷新 API
**不包含**: 第三方 OAuth 整合（將在另一份文件中說明）

[... 其他章節 ...]
```
