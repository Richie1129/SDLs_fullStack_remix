# Incident Response 事件回應

## 概述

此 skill 提供生產環境事件回應指引，確保能快速有效地處理問題。

## 適用角色

| 角色 | 職責 |
|------|------|
| **Incident Commander** | 協調處理 |
| **On-call** | 第一線回應 |
| **Tech Lead** | 技術決策 |

---

## 1. 事件嚴重度

| 等級 | 定義 | 範例 | SLA |
|------|------|------|-----|
| **SEV1** | 全面中斷 | 所有用戶無法使用 | 15 分鐘 |
| **SEV2** | 部分中斷 | 核心功能受損 | 30 分鐘 |
| **SEV3** | 功能異常 | 次要功能問題 | 4 小時 |
| **SEV4** | 輕微問題 | 不影響使用 | 1 天 |

---

## 2. 回應流程

```
告警觸發 → 確認問題 → 評估嚴重度 → 緩解 → 根本解決 → 事後檢討
```

### 詳細步驟

1. **確認問題** (5 分鐘)
   - 查看監控儀表板
   - 確認影響範圍

2. **呼叫支援** (如需要)
   - 升級嚴重度
   - 召集相關人員

3. **溝通** (持續)
   - 更新狀態頁面
   - 通知利害關係人

4. **緩解** (優先)
   - 快速止血
   - 考慮回滾

5. **修復** (後續)
   - 根本原因修復
   - 部署修補

## 3. On-Call 職責

### 輪班制度

| 項目 | 設定 |
|------|------|
| 輪班週期 | 每週輪換 |
| 交接時間 | 週一 09:00 |
| 回應時間 | < 15 分鐘 |
| 備援機制 | 次要 On-call |

### On-call 工具

- **PagerDuty** - 告警呼叫
- **Slack** - 團隊溝通
- **Runbook** - 處理指南

---

## 4. 事件溝通模板

```markdown
# 事件通知

## 狀態: 調查中 ⚠️

### 摘要
[簡述問題]

### 影響
- 受影響服務：[服務名稱]
- 受影響用戶：[百分比/數量]

### 時間軸
- HH:MM - 發現問題
- HH:MM - 開始調查
- HH:MM - [下次更新時間]

### 下一步
[目前正在做什麼]

---
Incident Commander: @name
更新頻率: 每 30 分鐘
```

---

## 5. 升級路徑

```
On-call → Tech Lead → Engineering Manager → CTO
           (15 min)      (30 min)          (1 hr)
```

| 情況 | 升級到 |
|------|--------|
| 無法緩解 | Tech Lead |
| SEV1 持續 30 分鐘 | Engineering Manager |
| 涉及資安 | Security Team |
| 需要公關 | PR Team |

---

## 6. 事件記錄

```markdown
# INC-2024-001: API 服務中斷

## 基本資訊
- 開始時間: 2024-01-20 14:30 UTC
- 結束時間: 2024-01-20 15:45 UTC
- 持續時間: 75 分鐘
- 嚴重度: SEV1

## 時間軸
| 時間 | 事件 |
|------|------|
| 14:30 | 收到告警 |
| 14:35 | 確認服務中斷 |
| 14:45 | 識別資料庫連線問題 |
| 15:00 | 重啟資料庫連線池 |
| 15:15 | 服務恢復 |
| 15:45 | 全面驗證完成 |

## 影響
- 全部用戶 75 分鐘無法使用
```

## 檢查清單

### 事件發生時
- [ ] 確認問題範圍
- [ ] 評估嚴重度
- [ ] 通知相關人員
- [ ] 記錄時間軸
- [ ] 更新狀態頁面

### 事件後
- [ ] 撰寫事件報告
- [ ] 安排 Postmortem
- [ ] 追蹤改善項目
