# 基礎設施設計 (Infrastructure Design)

## 概述
此 skill 協助設計完整的基礎設施架構，包括雲端資源規劃、網路架構、計算資源、儲存方案、安全設計和災難恢復策略，確保系統具有高可用性、可擴展性和安全性。

## 適用角色
- **主要負責**: DevOps 工程師、雲端架構師、SRE
- **協作角色**: 系統架構師、資安工程師、網路工程師

## 輸入需求
使用者需要提供：
- 系統架構和技術堆疊
- 效能需求和 SLA 目標
- 預算限制
- 合規要求
- 團隊技能水平

範例：`請幫我設計一個支援 10 萬並發用戶的 Web 應用基礎設施，使用 AWS`

## 執行步驟

### 步驟 1: 需求分析
- 了解系統需求
- 定義 SLA 目標
- 評估預算和限制

### 步驟 2: 架構設計
- 選擇雲端平台
- 設計網路拓撲
- 規劃計算和儲存資源

### 步驟 3: 安全設計
- 設計安全邊界
- 定義存取控制
- 規劃加密策略

### 步驟 4: 高可用設計
- 設計故障轉移
- 規劃備份策略
- 定義災難恢復

### 步驟 5: 成本優化
- 評估資源使用
- 選擇定價方案
- 規劃自動擴縮

### 2.2 流量路徑

1. 用戶請求 → Route 53 → CloudFront
2. 靜態資源 → CloudFront 快取 → S3
3. API 請求 → ALB → EKS Pod → RDS/Redis
4. 非同步任務 → RabbitMQ → Worker Pod

## 3. 網路架構

### 3.1 VPC 設計

| 項目 | 值 | 說明 |
|------|-----|------|
| VPC CIDR | 10.0.0.0/16 | 65,536 個 IP |
| Public Subnet | 10.0.1.0/24, 10.0.4.0/24 | 多 AZ |
| Private Subnet | 10.0.2.0/24, 10.0.5.0/24 | 應用層 |
| Data Subnet | 10.0.3.0/24, 10.0.6.0/24 | 資料層 |

### 3.2 安全群組

| 群組名稱 | 入站規則 | 出站規則 | 用途 |
|----------|----------|----------|------|
| alb-sg | 443 from 0.0.0.0/0 | All | 負載均衡器 |
| app-sg | 8080 from alb-sg | All | 應用伺服器 |
| db-sg | 5432 from app-sg | None | 資料庫 |
| redis-sg | 6379 from app-sg | None | Redis |

### 3.3 網路存取控制

```yaml
# NACL 規則
Public Subnet:
  Inbound:
    - 443 (HTTPS) from 0.0.0.0/0
    - 80 (HTTP) from 0.0.0.0/0 (重導向用)
  Outbound:
    - All traffic

Private Subnet:
  Inbound:
    - All from 10.0.0.0/16
  Outbound:
    - 443 to 0.0.0.0/0 (NAT)

Data Subnet:
  Inbound:
    - 5432, 6379 from 10.0.2.0/24
  Outbound:
    - None (無對外連線需求)
```

## 4. 計算資源

### 4.1 EKS 叢集配置

| 項目 | 配置 | 說明 |
|------|------|------|
| Kubernetes 版本 | 1.28 | 穩定版本 |
| 節點類型 | m5.xlarge | 4 vCPU, 16 GB |
| 節點數量 | 3-10 | Auto Scaling |
| Pod 最大數 | 110 per node | AWS CNI 限制 |

### 4.2 應用部署規格

| 服務 | Replicas | CPU Request | Memory Request | HPA |
|------|----------|-------------|----------------|-----|
| API Server | 3-10 | 500m | 1Gi | CPU > 70% |
| Worker | 2-5 | 250m | 512Mi | Queue depth |
| Nginx | 2-4 | 100m | 128Mi | - |

### 4.3 Auto Scaling 策略

```yaml
# Horizontal Pod Autoscaler
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: api-server-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: api-server
  minReplicas: 3
  maxReplicas: 10
  metrics:
    - type: Resource
      resource:
        name: cpu
        target:
          type: Utilization
          averageUtilization: 70
```

## 6. 安全設計

### 6.1 身份與存取管理

```yaml
# IAM 角色設計
Application Role:
  - S3: Read/Write to uploads bucket
  - Secrets Manager: Read secrets
  - CloudWatch: Write logs and metrics

CI/CD Role:
  - ECR: Push images
  - EKS: Deploy applications
  - S3: Read/Write to assets bucket

DBA Role:
  - RDS: Full access
  - Secrets Manager: Manage DB secrets
```

### 6.2 密鑰管理

| 密鑰類型 | 儲存位置 | 輪換週期 |
|----------|----------|----------|
| DB 密碼 | Secrets Manager | 30 天 |
| API Keys | Secrets Manager | 90 天 |
| TLS 憑證 | ACM | 自動 |

### 6.3 安全掃描

## 8. 災難恢復

### 8.1 備份策略

| 資源 | 備份頻率 | 保留期間 | 備份位置 |
|------|----------|----------|----------|
| RDS | 每日 + 5 分鐘 Logs | 7 天 | 同區域 + 跨區域 |
| Redis | 每日快照 | 7 天 | 同區域 |
| S3 | 跨區域複製 | - | ap-southeast-1 |
| EKS | etcd 備份 | 7 天 | S3 |

### 8.2 災難恢復計畫

| 場景 | RTO | RPO | 恢復步驟 |
|------|-----|-----|----------|
| 單一 AZ 故障 | 0 | 0 | 自動故障轉移 |
| 整個區域故障 | 4 小時 | 1 小時 | 啟用 DR 站點 |
| 資料毀損 | 2 小時 | 1 小時 | 從備份還原 |

### 8.3 DR 架構

```
主要區域 (ap-northeast-1)          DR 區域 (ap-southeast-1)
┌─────────────────────┐          ┌─────────────────────┐
│  EKS Cluster        │          │  EKS Cluster        │
│  (Active)           │          │  (Standby)          │
├─────────────────────┤          ├─────────────────────┤
│  RDS Primary        │──複製──► │  RDS Read Replica   │
├─────────────────────┤          ├─────────────────────┤
│  S3 Bucket          │──複製──► │  S3 Bucket          │

## 9. 成本估算

### 9.1 月度成本 (USD)

| 服務 | 配置 | 月費 |
|------|------|------|
| EKS | 叢集 + 3 節點 | $450 |
| RDS | db.r5.xlarge Multi-AZ | $700 |
| ElastiCache | 3 節點叢集 | $350 |
| ALB | 1 個 + 流量 | $100 |
| CloudFront | 1 TB 流量 | $85 |
| S3 | 500 GB + 請求 | $30 |
| Route 53 | 1 Hosted Zone | $5 |
| NAT Gateway | 2 個 + 流量 | $100 |
| CloudWatch | 監控和日誌 | $50 |
| 其他 | KMS, Secrets Manager | $30 |
| **總計** | | **~$1,900** |

### 9.2 成本優化建議

1. **Reserved Instances**: RDS 和 EC2 使用 1 年 RI 可節省 30%
2. **Spot Instances**: Worker 節點可使用 Spot 節省 60%
3. **S3 生命週期**: 自動轉換儲存類別
4. **右尺寸調整**: 定期審查資源使用
