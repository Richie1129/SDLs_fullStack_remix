# 變更日誌模板

## 概述
此 skill 提供變更日誌（Changelog）模板，遵循 [Keep a Changelog](https://keepachangelog.com/) 規範，幫助團隊系統化地記錄專案的版本更新、功能變更、bug 修復等內容，便於使用者和團隊成員追蹤專案演進。

## 適用角色
- **主要負責**: 發布經理、產品經理、技術主管
- **協作角色**: 開發團隊、QA 團隊、技術寫手

## 輸入需求
使用者需要提供：
- 版本號（遵循語意化版本 Semantic Versioning）
- 本次發布的變更內容
- 變更類型（新增、變更、棄用、移除、修復、安全）

範例：`請幫我建立版本 [版本號] 的變更日誌，包含 [變更內容簡述]`

## 執行步驟

### 步驟 1: 確認版本資訊
- 確認版本號（主版本.次版本.修訂版本）
- 確認發布日期
- 確認發布類型（重大更新/次要更新/修補）

### 步驟 2: 收集變更內容
- 從 Git commit、PR、Jira ticket 等收集變更資訊
- 將變更按類型分類
- 識別破壞性變更

### 步驟 3: 撰寫變更說明
- 使用使用者友善的語言
- 每個變更項目簡潔明確
- 包含相關 issue/PR 連結

### 步驟 4: 格式化輸出
- 按照標準格式組織內容
- 添加版本比較連結
- 更新未發布區塊

## 變更類型說明

本專案的變更日誌使用以下類型：

- **新增 (Added)**: 新功能
- **變更 (Changed)**: 現有功能的變更
- **棄用 (Deprecated)**: 即將移除的功能
- **移除 (Removed)**: 已移除的功能
- **修復 (Fixed)**: Bug 修復
- **安全 (Security)**: 安全性相關更新

## 語意化版本說明

版本格式：`主版本.次版本.修訂版本` (MAJOR.MINOR.PATCH)

- **主版本 (MAJOR)**: 不相容的 API 變更
- **次版本 (MINOR)**: 向下相容的新功能
- **修訂版本 (PATCH)**: 向下相容的 Bug 修復

範例：
- `1.0.0` → `2.0.0`: 包含破壞性變更
- `1.0.0` → `1.1.0`: 新增功能，但向下相容
- `1.0.0` → `1.0.1`: Bug 修復

## 維護指引

### 新增變更記錄

1. 在開發過程中，將變更添加到「未發布」區塊
2. 每個 PR 都應更新 CHANGELOG.md
3. 使用清晰的使用者導向語言，避免技術術語

### 發布新版本

1. 將「未發布」區塊的內容移至新版本區塊
2. 確定版本號（根據變更類型）
3. 添加發布日期
4. 撰寫「重點功能」摘要
5. 更新版本比較連結
6. 建立 Git tag

### 撰寫原則

- **使用者視角**: 從使用者角度描述變更，而非實作細節
  - ✅ 好: "登入速度提升 50%"
  - ❌ 差: "優化了資料庫查詢的 N+1 問題"
- **具體明確**: 提供具體資訊，避免模糊描述
  - ✅ 好: "新增匯出 CSV 功能，支援最多 10,000 筆資料"
  - ❌ 差: "改進匯出功能"
- **包含連結**: 連結到相關 issue、PR 或文件
- **標記重要性**: 使用 ⚠️ 標記破壞性變更，🔒 標記安全更新

## 範例

### 輸入範例
```
請幫我建立版本 2.1.0 的變更日誌，包含：
1. 新增深色模式功能
2. 修復文件上傳 bug
3. 效能優化：首頁載入速度提升 40%
4. 更新 React 至 18.2.0
```

  - 儲存使用者偏好設定

### 變更 (Changed)

#### 改進 (Improvements)
- **效能優化**: 首頁載入速度提升 40%，從平均 2.5 秒減少至 1.5 秒 ([#258](link))

  - 減少初始 JavaScript 包大小

### 修復 (Fixed)

#### Bug 修復
- 修復大型檔案（>10MB）上傳時連線逾時的問題 ([#259](link))
- 修復上傳進度條在某些瀏覽器不顯示的問題 ([#260](link))

### 依賴更新 (Dependencies)

#### 主要更新
- React 從 18.0.0 升級至 18.2.0
  - 改進並發渲染效能
  - 修復已知問題
  - 更好的 TypeScript 支援

### 感謝 (Contributors)

感謝以下貢獻者讓本次發布成為可能：
