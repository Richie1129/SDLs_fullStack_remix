# 內容設計 (Content Design)

## 概述
此 skill 協助建立產品內容設計規範，涵蓋文案撰寫原則、品牌語調 (Voice & Tone)、UX Writing 指南、微文案 (Microcopy) 標準，確保產品溝通一致且有效。

## 適用角色
- **主要負責**: UX Writer、內容策略師、產品設計師
- **協作角色**: 產品經理、品牌經理、行銷團隊、本地化團隊

## 輸入需求
使用者需要提供：
- 產品類型和目標受眾
- 品牌定位和價值觀
- 現有內容風格（如有）
- 競品內容參考
- 支援語言和地區

範例：`請幫我建立 B2B SaaS 產品的內容設計指南，目標受眾是中小企業主`

## 執行步驟

### 步驟 1: 定義品牌語調
- 確立品牌個性
- 建立語調光譜
- 定義情境變化

### 步驟 2: 建立寫作原則
- 清晰優先
- 簡潔有力
- 以使用者為中心
- 一致性

### 步驟 3: 制定元件文案規範
- 按鈕和 CTA
- 表單標籤和提示
- 錯誤訊息
- 空狀態
- 通知和提醒

### 步驟 4: 建立術語表
- 產品特定術語
- 動詞使用規範
- 禁用詞彙

### 步驟 5: 本地化指南
- 翻譯注意事項
- 文化適應
- 長度考量

## 1. 品牌語調 (Voice & Tone)

### 1.1 品牌個性

我們的品牌像是一位 **[描述：例如「專業但平易近人的顧問」]**。

**我們是**:
- 專業的 (Professional)
- 友善的 (Friendly)
- 可靠的 (Trustworthy)
- 幫助的 (Helpful)

**我們不是**:
- 傲慢的 (Arrogant)
- 機械式的 (Robotic)
- 推銷感重的 (Salesy)
- 過於隨便的 (Too casual)

### 1.2 語調光譜

```
正式 ←————●————→ 輕鬆
嚴肅 ←——●——————→ 幽默
權威 ←————●————→ 平易近人
保守 ←——————●——→ 創新
```

### 1.3 情境語調變化

| 情境 | 語調調整 | 範例 |
|------|----------|------|
| 成功完成 | 積極、鼓勵 | 「太棒了！您的設定已完成。」 |
| 錯誤發生 | 冷靜、幫助 | 「發生了一點問題，讓我們來解決它。」 |
| 敏感操作 | 謹慎、清晰 | 「此操作將永久刪除您的資料，且無法復原。」 |
| 等待載入 | 輕鬆、保持連結 | 「正在為您準備中...」 |
| 空狀態 | 引導、鼓勵行動 | 「這裡還沒有任何項目，立即建立第一個吧！」 |
| 入門引導 | 熱情、支持 | 「歡迎加入！讓我們花 2 分鐘完成設定。」 |

### 1.4 語調範例對比

**❌ 太正式 / 冷漠**:
> "系統無法處理您的請求。請稍後再試或聯繫客服人員。"

**❌ 太隨便 / 不專業**:
> "哎呀～壞掉了 😅 再試一次看看唄！"

**✅ 恰到好處**:
> "目前無法完成此操作。您可以稍後再試，或聯繫我們取得協助。"

## 2. 寫作原則

### 2.1 清晰優先 (Clarity First)

**原則**: 使用者應該一次就能理解

**執行方式**:
- 使用常見詞彙，避免專業術語
- 一句話只表達一個概念
- 主動語態優於被動語態

```
❌ 「您的帳戶已被系統停用。」
✅ 「我們已暫停您的帳戶。」

❌ 「驗證流程需在 24 小時內完成。」
✅ 「請在 24 小時內完成驗證。」
```

### 2.2 簡潔有力 (Concise & Impactful)

**原則**: 用最少的字傳達完整的意思

**執行方式**:
- 刪除不必要的字詞
- 避免重複說明
- 數字用阿拉伯數字

```
❌ 「請您點擊下方的按鈕以便進行下一步操作。」
✅ 「點擊下方按鈕繼續。」

❌ 「您已經成功地完成了註冊的流程。」
✅ 「註冊完成！」
```

### 2.3 以使用者為中心 (User-Centric)

**原則**: 從使用者角度出發，說明對他們的好處

**執行方式**:
- 使用「您」而非「我們」
- 說明好處而非功能
- 給予使用者掌控感

```
❌ 「我們的演算法會分析您的資料。」
✅ 「系統會根據您的使用習慣提供個人化推薦。」

❌ 「新功能：批次上傳」
✅ 「一次上傳多個檔案，節省您的時間」
```

### 2.4 一致性 (Consistency)

**原則**: 相同概念使用相同詞彙

**執行方式**:
- 遵循術語表
- 統一格式規範
- 維持語調一致

```
❌ 登入 / 登錄 / Sign in（混用）
✅ 統一使用「登入」

❌ 儲存 / 存檔 / 保存（混用）
✅ 統一使用「儲存」
```

## 3. UI 文案規範

### 3.1 按鈕和 CTA (Call to Action)

**原則**:
- 使用動詞開頭
- 明確表達結果
- 2-4 個字為佳

| 類型 | ✅ 好 | ❌ 不好 |
|------|-------|--------|
| 主要動作 | 儲存變更 | OK |
| 確認動作 | 刪除專案 | 是的 |
| 取消動作 | 取消 | 不要 |
| 導航動作 | 查看詳情 | 點此 |
| 建立動作 | 新增項目 | 新建 |

**確認對話框按鈕**:
```
標題：刪除此專案？
說明：此操作無法復原，專案中的所有資料都會被刪除。

[取消] [刪除專案]  ← 按鈕文字要具體
```

### 3.2 表單標籤和說明

**標籤 (Label)**:
- 簡短明確
- 使用名詞或名詞片語
- 必填欄位加 * 號

```
✅ 電子郵件 *
✅ 公司名稱
❌ 請輸入您的電子郵件地址 *
```

**佔位文字 (Placeholder)**:
- 提供範例格式
- 不要重複標籤
- 淺色顯示

```
標籤：電子郵件 *
佔位：name@company.com

標籤：電話號碼
佔位：09xx-xxx-xxx
```

**輔助說明 (Helper Text)**:
- 提供額外說明
- 說明格式要求
- 放在輸入框下方

```
密碼 *
[________________]
至少 8 個字元，包含大小寫字母和數字
```

### 3.3 錯誤訊息

**原則**:
1. 說明發生了什麼
2. 說明如何修正
3. 避免責怪使用者

**公式**: [問題] + [解決方式]

| 情境 | ✅ 好 | ❌ 不好 |
|------|-------|--------|
| 必填未填 | 請輸入電子郵件 | 此欄位為必填 |
| 格式錯誤 | 請輸入有效的電子郵件格式 | 格式錯誤 |
| 密碼不符 | 密碼不相符，請再確認一次 | 錯誤 |
| 網路問題 | 無法連線，請檢查網路後再試 | Error 500 |

### 3.4 成功訊息

**原則**:
- 確認動作已完成
- 說明下一步（如需要）
- 適度慶祝

```
✅ 「設定已儲存」
✅ 「專案建立成功！前往專案 →」
✅ 「密碼已更新，下次登入請使用新密碼」
```

### 3.5 空狀態

**原則**:
- 說明此處通常顯示什麼
- 引導如何開始
- 保持正面語調

**模板**:
```
[圖示]
[標題：描述空狀態]
[說明：為什麼是空的 + 如何開始]
[CTA 按鈕]
```

**範例**:
```
📊
尚無資料
專案建立後，分析報告會顯示在這裡。
[建立第一個專案]
```

### 3.6 載入狀態

**原則**:
- 說明正在發生什麼
- 適當時顯示進度
- 時間長時提供預期

```
✅ 「載入中...」
✅ 「正在上傳（3/10）...」
✅ 「分析資料中，大約需要 30 秒...」
❌ 「Loading...」（避免英文）
```

### 3.7 通知和提醒

**類型規範**:

| 類型 | 圖示 | 使用時機 | 範例 |
|------|------|----------|------|
| 成功 | ✓ 綠色 | 操作完成 | 「變更已儲存」 |
| 錯誤 | ✕ 紅色 | 操作失敗 | 「無法刪除，請稍後再試」 |
| 警告 | ⚠ 黃色 | 需要注意 | 「您的方案將於 3 天後到期」 |
| 資訊 | ℹ 藍色 | 一般通知 | 「已推出新功能，立即體驗」 |

## 4. 常見情境指南

### 4.1 入門引導 (Onboarding)

**目標**: 讓使用者快速上手，感受價值

**原則**:
- 歡迎但不囉嗦
- 強調好處
- 降低門檻

**範例流程**:
```
歡迎使用 [產品名稱]！
讓我們花 2 分鐘完成設定，您就能開始使用了。

步驟 1/3：建立您的工作區
為您的工作區取個名字，方便辨識。
工作區名稱 *
[我的工作區        ]
[下一步]
```

### 4.2 權限請求

**原則**:
- 先說明價值，再請求
- 不要一次要求所有權限
- 提供略過選項

```
✅
開啟通知提醒
在重要事件發生時，我們會即時通知您，不錯過任何更新。
[開啟通知] [稍後再說]

❌
我們需要通知權限
[允許] [拒絕]
```

### 4.3 付費升級

**原則**:
- 強調價值而非限制
- 避免壓力推銷
- 提供清楚的方案比較

```
✅
升級解鎖更多功能
進階方案讓您享有無限專案、優先客服和進階分析。
[查看方案] [先繼續使用免費版]

❌
您已達到免費版上限！
立即升級才能繼續使用。
[升級]
```

### 4.4 危險操作

**原則**:
- 清楚說明後果
- 要求明確確認
- 提供退路

```
刪除帳戶

⚠️ 此操作無法復原

刪除帳戶後，以下資料將被永久刪除：
• 所有專案和資料
• 帳單記錄
• 團隊成員設定

如要繼續，請輸入您的帳戶名稱「[帳戶名稱]」確認。
[________________]

[取消] [永久刪除帳戶]
```

### 4.5 錯誤頁面

**404 頁面**:
```
🔍
找不到頁面
您要找的頁面可能已移除、改名，或暫時無法使用。

[返回首頁] [回上一頁]
```

**500 頁面**:
```
⚠️
發生了一些問題
我們正在處理中，請稍後再試。
如問題持續，請聯繫客服。

[重新整理] [聯繫客服]
```

## 5. 術語表

### 5.1 產品術語

| 術語 | 定義 | 使用情境 |
|------|------|----------|
| 工作區 | 團隊協作的頂層容器 | 「建立新工作區」 |
| 專案 | 工作區下的任務集合 | 「新增專案」 |
| 成員 | 工作區或專案中的人員 | 「邀請成員」 |
| 方案 | 訂閱的服務層級 | 「目前方案：專業版」 |

### 5.2 動詞規範

| 動作類型 | 使用詞彙 | 避免詞彙 |
|----------|----------|----------|
| 建立 | 新增、建立 | 創建、新建 |
| 修改 | 編輯 | 修改、更改 |
| 刪除 | 刪除 | 移除、清除 |
| 確認 | 確認、確定 | OK、好的 |
| 取消 | 取消 | 返回、不要 |
| 儲存 | 儲存 | 保存、存檔 |
| 登入 | 登入 | 登錄、Sign in |
| 登出 | 登出 | 登出、Sign out |

### 5.3 禁用詞彙

| 禁用 | 原因 | 替代 |
|------|------|------|
| 用戶 | 生硬 | 使用者、您 |
| 功能 | 太技術 | 說明具體用途 |
| 點擊 | 不夠精確 | 選擇、點選 |
| 親 | 過於隨便 | 您 |
| 噢不 | 不專業 | 避免使用 |

## 6. 本地化指南

### 6.1 翻譯注意事項

**保留不翻譯**:
- 產品名稱
- 技術術語（如 API、URL）
- 品牌相關詞彙

**文字長度考量**:
- 中文通常比英文短
- 預留 30% 空間給較長語言（如德文）
- 按鈕文字考慮換行

### 6.2 文化適應

| 項目 | 台灣繁體 | 中國簡體 | 說明 |
|------|----------|----------|------|
| 貨幣 | NT$ | ¥ | 注意符號位置 |
| 日期 | YYYY/MM/DD | YYYY-MM-DD | 格式不同 |
| 電話 | 09xx-xxx-xxx | 1xx-xxxx-xxxx | 格式不同 |

### 6.3 翻譯檢查清單

- [ ] 語法正確
- [ ] 術語一致
- [ ] 長度適當
- [ ] 文化適當
- [ ] 數字格式正確
- [ ] 日期格式正確

## 7. 檢查清單

### 7.1 發布前檢查

**清晰度**:
- [ ] 主旨明確，一看就懂
- [ ] 沒有專業術語或已解釋
- [ ] 使用主動語態

**一致性**:
- [ ] 術語使用一致
- [ ] 語調符合品牌
- [ ] 格式規範統一

**完整性**:
- [ ] 錯誤訊息提供解決方式
- [ ] 空狀態有引導行動
- [ ] 確認對話框說明清楚

**無障礙**:
- [ ] alt 文字描述適當
- [ ] 不僅靠顏色傳達資訊
- [ ] 連結文字有意義
