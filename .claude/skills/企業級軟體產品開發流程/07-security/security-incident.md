# Security Incident 安全事件處理

## 概述

此 skill 提供安全事件回應指引，確保能快速有效地處理安全事件，降低損害。

## 適用角色

| 角色 | 職責 |
|------|------|
| **事件指揮** | 安全主管 |
| **調查員** | 安全工程師 |
| **支援** | DevOps、開發、法務 |

---

## 1. 事件嚴重度

| 等級 | 定義 | 範例 | 回應時間 |
|------|------|------|---------|
| **P0** | 重大資料外洩、系統被控制 | 用戶資料外洩 | 立即 |
| **P1** | 部分資料洩露、服務受影響 | API 金鑰外洩 | 1 小時 |
| **P2** | 潛在威脅、需要調查 | 異常登入模式 | 4 小時 |
| **P3** | 低風險、資訊性 | 掃描嘗試 | 1 工作天 |

---

## 2. 事件回應流程

```
識別 → 遏制 → 根除 → 恢復 → 經驗教訓
```

### 2.1 識別 (Identification)

- 確認是否為安全事件
- 評估嚴重度
- 通知相關人員

### 2.2 遏制 (Containment)

```bash
# 短期遏制
- 隔離受影響系統
- 暫停可疑帳號
- 阻擋攻擊 IP

# 長期遏制
- 部署臨時修補
- 加強監控
```

### 2.3 根除 (Eradication)

- 移除惡意程式
- 修補漏洞
- 更換憑證

### 2.4 恢復 (Recovery)

- 系統復原
- 驗證安全性
- 恢復正常運作

### 2.5 經驗教訓 (Lessons Learned)

- 撰寫事後報告
- 更新流程
- 改善監控

---

## 3. 通報流程

```
發現者 → 安全團隊 → 事件指揮官
           │
           ├── 技術團隊
           ├── 管理層
           └── 法務/公關（如需要）
```

### 外部通報

| 情況 | 通報對象 | 時限 |
|------|---------|------|
| 個資外洩 (GDPR) | 監管機關 | 72 小時 |
| 資安事件 (台灣) | 主管機關 | 1 小時內 |
| 信用卡外洩 | 信用卡組織 | 立即 |

---

## 4. 事件報告模板

```markdown
# 安全事件報告

## 事件摘要
- **事件 ID**: INC-2024-001
- **嚴重度**: P1
- **狀態**: 已解決
- **發生時間**: 2024-01-20 14:30 UTC
- **解決時間**: 2024-01-20 18:45 UTC

## 影響
- 受影響用戶數：1,234
- 外洩資料類型：Email、姓名
- 業務影響：API 停機 4 小時

## 時間軸
| 時間 | 事件 |
|------|------|
| 14:30 | 監控告警：異常 API 流量 |
| 14:35 | 確認為攻擊，啟動事件回應 |
| 15:00 | 阻擋攻擊 IP，遏制完成 |
| 17:00 | 漏洞修補完成 |
| 18:45 | 驗證通過，恢復服務 |

## 根本原因
- API 端點存在 IDOR 漏洞
- 缺乏速率限制

## 修復措施
1. 修補 IDOR 漏洞
2. 新增 API Rate Limiting
3. 加強存取日誌監控

## 改善建議
1. 加強安全審查流程
2. 定期滲透測試
3. 員工安全培訓
```
