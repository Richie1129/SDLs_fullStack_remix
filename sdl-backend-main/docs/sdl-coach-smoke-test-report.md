## 觀察與分析（v4 — 截斷觀測 + 錨點策略 + maxTokens 餘裕）

### 修正動機

v3 雖然把字數壓到 333，但使用者擔憂：硬限 `maxTokens=600` 會在 LLM 寫到邊界時中途砍斷結尾句（例如把「…你們打算先從哪個指標開始？」的問號砍掉）。雖然 v3 實測 48/50 自然結尾，但沒有可觀測訊號證明「沒被截斷」。

### 修法

1. **加觀測**：`callVLLM` 回傳 `finish_reason`，`length` 代表真被 maxTokens 砍
2. **放寬硬封頂**：`maxTokens 600 → 800`（對應 ~450 中文字，留 1.5× 餘裕）
3. **錨點反推**：user prompt 從「不超過 300 字」改「嚴格 250 字」—— 利用 LLM 會略超錨點（+10-20%）的傾向，反推到 280-310 字區間
4. **加規則 4**：「結尾務必用完整一句收尾，不要在列點中途結束」
5. **截斷顯示化**：若 `finish_reason=length`，console.warn 並在 answer 尾端加「（上面回應超過長度上限被截斷，你可以再問我繼續哪個部分。）」讓學生看得到
6. **audit 記錄**：metadata 加 `answerChars` 與 `truncated`，供長期監控

### 關鍵結論

1. **截斷不是真問題（經實測證實）**：50 題中 0 次 `finish_reason=length`。錨點 250 讓 LLM 自然收在 280-310，沒有逼近 maxTokens 的案例
2. **首度達成 300 字守則**：平均 296 字、≥300 字只剩 17 題（34%），是四輪中唯一真正貼合守則的
3. **速度 −11%**：回答更短，LLM 生成時間連帶下降到 5.6s
4. **其他優點維持**：你們組 54 次、違規 0、幻覺 0、看板雜訊 0 — 前幾輪累積的成果沒有因縮短而流失

### Trade-off

- 🟡 **具體數據引用從 8 降到 3**：回答縮短後，LLM 省掉了一些「順便提一下 pH 5.8 的數值」類的輕量引用。教育價值略損，但可接受
- 🟡 **17/50 題仍微超 300 字**：LLM 寫到 302-335 區間，嚴格來說超標但無實際教育問題。硬要壓到全部 ≤300 需 post-processing 截斷，反而會砍掉結尾句
