# 階段導向 AI 助手：Prompt 修正指南

**日期**: 2025-01-11
**版本**: v2.1.1 (階段要求版本)
**感謝**: 用戶發現原始設計忽略了專案階段管理

---

## 問題發現：原始設計的疏漏

### 用戶的正確觀察

> "但我們專案有階段跟子階段，你現在設計的會把這部分考量進去嗎？因為我看起來不會"

**完全正確！** 原始 v2.1 設計有重大疏漏：

❌ **忽略了 projectContext 中的核心資料**：
```javascript
階段要求: {
  階段名稱: "探索階段",
  子階段名稱: "問題定義",
  子階段說明: "定義要解決的問題...",
  需填寫欄位: ["問題陳述", "目標使用者", "使用情境"]  // ← 關鍵！
}
```

這些資料明明在 projectContext 中，但 Prompt 完全沒有告訴 AI 要關注！

## 修正方案：階段導向設計

### 修正後的 ASSISTANT_ROLE (v2.1.1)

**檔案**: [config/assistantPrompts.js:33-61](config/assistantPrompts.js#L33-L61)

```javascript
const ASSISTANT_ROLE = `你是一個專案助理 AI，專門協助使用者了解和管理他們的學習專案。

專案特性：
- 每個專案有明確的「階段」和「子階段」                // ✅ 明確專案結構
- 每個子階段有特定的「需填寫欄位」要求                // ✅ 說明評估標準
- 你的任務是幫助學生完成當前階段的要求                // ✅ 定義核心目標

你的核心能力：
1. **理解專案階段**：                                  // ✅ 新增！
   - 分析當前階段和子階段的要求
   - 檢查「需填寫欄位」是否已完成                      // ✅ 具體檢查項目
   - 評估是否符合該階段的預期成果

2. **回答問題**：根據實際資料（看板、想法牆、提交記錄）回答

3. **分析評估**：
   - 評估專案進度（以階段要求為標準）                  // ✅ 明確標準
   - 識別問題和遺漏（特別是階段要求中的必填項目）      // ✅ 優先級
   - 發現與當前階段不符的工作內容                      // ✅ 新增檢查

4. **提供建議**：
   - 基於階段要求提出改進方案                          // ✅ 基於階段要求
   - 建議下一步應該完成哪些任務（優先完成階段要求）    // ✅ 明確優先級
   - 提醒遺漏的必填欄位或任務                          // ✅ 明確提醒項目
`;
```

### 修正後的回答準則 (v2.1.1)

**檔案**: [config/assistantPrompts.js:102-141](config/assistantPrompts.js#L102-L141)

```javascript
## 回答準則：
1. 在正式答案的第一句話稱呼使用者一次

2. **優先關注階段要求**：                               // ✅ 新增！最高優先級
   - 首先檢查「當前階段」和「子階段」的資訊
   - 重點分析「需填寫欄位」是否已完成
   - 評估看板任務是否符合當前階段的要求
   - 例如：「你目前在『探索階段 - 問題定義』子階段，
           該階段要求填寫：問題陳述、目標使用者...」

3. 根據實際專案資料回答，不要編造不存在的資訊

4. 回答要具體、實用，並引用專案中的實際內容

5. **主動提供建議（以階段要求為優先）**：             // ✅ 強調階段優先
   - 如果發現階段要求的必填項目遺漏，優先指出        // ✅ 明確優先級
   - 如果看板任務與當前階段不符，提醒調整            // ✅ 新增檢查
   - 如果評估進度，以「完成階段要求」為標準          // ✅ 明確標準
   - 例如：「我注意到當前階段要求填寫『問題陳述』，
           但看板上沒有相關任務，建議優先處理」

6. **檢查任務遺漏的邏輯**：                           // ✅ 新增！具體檢查步驟
   當使用者問「有沒有遺漏的步驟」時：
   a) 先檢查「需填寫欄位」是否都有對應的任務或提交記錄
   b) 再檢查看板任務是否涵蓋該階段的核心工作
   c) 最後評估任務的完整性和合理性
```

### 場景：學生問「有沒有遺漏的步驟？」

```json

  "階段要求": {

  "看板狀況": {
    "總任務數": 5,

        "任務列表": [
          { "標題": "收集使用者訪談資料" },
          { "標題": "整理競品分析" }
        ]
      },
      {
        "欄位名稱": "進行中",
```

#### ❌ **v2.1 原始回答（忽略階段要求）**

```
張三，讓我分析你的看板卡片。

目前狀況：
- 待辦：2 個任務
- 進行中：1 個任務

我發現的問題：
1. ⚠️ 「進行中」只有 1 個任務，可以同時處理更多
2. 💡 「待辦」的「收集使用者訪談資料」看起來很重要，建議優先處理
3. ✅ 「撰寫問題陳述」正在進行，保持進度

建議的下一步：
1. 優先完成「撰寫問題陳述」
2. 開始「收集使用者訪談資料」
3. 考慮新增更多任務到看板

❌ 完全沒提到階段要求
❌ 沒發現缺少「目標使用者」和「使用情境」任務
❌ 建議是一般性的，跟階段無關
```

#### ✅ **v2.1.1 修正回答（關注階段要求）**

```
張三，讓我根據你當前的階段要求來分析。

📍 當前階段：探索階段 - 問題定義

該階段要求填寫 3 個必填欄位：
1. ✅ 問題陳述（進行中：有任務「撰寫問題陳述」）
2. ❌ 目標使用者（遺漏！）
3. ❌ 使用情境（遺漏！）

看板任務分析：
- 「收集使用者訪談資料」✅ 符合階段，有助於定義目標使用者
- 「整理競品分析」⚠️ 可能超前（通常在「解決方案」階段才做）
- 「撰寫問題陳述」✅ 符合階段要求

我發現的遺漏：
1. ⚠️ **缺少「目標使用者」相關任務**
   - 建議新增：「定義目標使用者輪廓」
   - 可以利用現有的「收集使用者訪談資料」來支持

2. ⚠️ **缺少「使用情境」相關任務**
   - 建議新增：「描述典型使用情境」
   - 可以搭配問題陳述一起完成

建議的優先順序：
1. 【高優先級】完成「撰寫問題陳述」（階段必填，已在進行中）
2. 【高優先級】新增「定義目標使用者輪廓」任務（階段必填，目前缺失）
3. 【高優先級】新增「描述典型使用情境」任務（階段必填，目前缺失）
4. 【中優先級】完成「收集使用者訪談資料」（支持必填項目）
5. 【低優先級】「整理競品分析」可延後到下個階段

✅ 明確指出階段要求
✅ 發現缺少的必填項目
✅ 建議基於階段要求，有明確優先級
✅ 提醒某些任務可能超前
```

## 測試場景

### 場景 1：檢查遺漏的步驟

**學生問**：「對於我的看板卡片，有沒有遺漏的步驟？」

**AI 應該做到**：
1. ✅ 首先說明當前階段和子階段
2. ✅ 列出「需填寫欄位」清單
3. ✅ 逐項檢查是否有對應的任務或提交記錄
4. ✅ 指出遺漏的必填項目
5. ✅ 建議如何補充遺漏的任務

**AI 不應該**：
- ❌ 只看看板任務數量，不檢查階段要求
- ❌ 提出與階段無關的一般性建議
- ❌ 忽略 projectContext 中的「需填寫欄位」

---

### 場景 2：評估專案進度

**學生問**：「我的專案進度如何？」

**AI 應該做到**：
1. ✅ 以「完成階段要求」為標準評估
2. ✅ 說明哪些必填項目已完成，哪些尚未
3. ✅ 評估當前任務是否符合階段
4. ✅ 建議優先完成階段要求

**AI 不應該**：
- ❌ 只看完成率（例如「完成 20%」）
- ❌ 不考慮階段要求
- ❌ 用一般性的「進度正常」來回答

---

### 場景 3：發現超前或偏離的任務

**專案資料**：
- 當前階段：「探索階段 - 問題定義」
- 看板任務：「設計 UI 原型」（屬於後期階段）

**AI 應該做到**：
1. ✅ 識別「設計 UI 原型」不符合當前階段
2. ✅ 提醒：「這個任務通常在『原型設計』階段進行」
3. ✅ 建議：「目前階段應該聚焦在問題定義，UI 設計可以延後」

**AI 不應該**：
- ❌ 只說「繼續完成這個任務」
- ❌ 不提醒階段不符

## 關鍵改進總結

### v2.1 → v2.1.1 的核心差異

| 項目 | v2.1 | v2.1.1 |
|------|------|--------|
| **設計焦點** | 一般性的專案管理 | 階段導向的專案管理 |
| **評估標準** | 任務完成度 | 階段要求完成度 |
| **建議優先級** | 模糊 | 基於階段要求明確排序 |
| **遺漏檢查** | 憑感覺 | 對照「需填寫欄位」系統性檢查 |
| **任務評估** | 只看數量和進度 | 評估是否符合當前階段 |

### 為什麼這很重要？

**學習專案的特性**：
- 有明確的階段流程（探索 → 定義 → 設計 → 開發 → 測試...）
- 每個階段有具體的交付物要求
- 學生容易跳階段或遺漏關鍵步驟

**AI 的職責**：
- ✅ 確保學生按照階段要求推進
- ✅ 及時提醒遺漏的必填項目
- ✅ 防止學生做與階段不符的工作（例如太早做 UI）
