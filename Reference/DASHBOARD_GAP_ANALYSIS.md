# SDL 學習儀表板差距分析報告

**分析日期:** 2026-03-25
**研究基礎:** 14 篇學術論文（2020–2025，全部已驗證真實存在）

---

## 儀表板架構與資料範圍

本系統共有 **4 個儀表板**，分為兩層。**理解資料範圍是正確分析缺口的前提。**

| 儀表板 | 路由 | 資料範圍 | 使用者 |
|--------|------|----------|--------|
| **學生總覽** `StudentOverview` | `/student-overview` | 該學生的所有專案（跨專案） | 學生 |
| **學生專案儀表板** `StudentDashboard` | `/project/:id/studentDashboard` | 單一專案內，該學生的表現 | 學生 |
| **教師總覽** `TeacherOverview` | `/teacher-overview` | 該教師指導的所有專案（跨專案） | 教師 |
| **教師專案儀表板** `TeacherDashboard` | `/project/:id/teacherDashboard` | 單一專案內，所有學生的表現 | 教師 |

### 關鍵架構限制

> **Stage 是 project-level 欄位**，不是 student-level。
> 同一個專案裡的所有學生，永遠在同一個 stage 和 sub-stage。
>
> 因此：
> - **「哪些組在哪個階段」** → 只在 **Teacher Overview** 有意義（跨多個不同專案）
> - **Teacher Dashboard 裡所有人同階段**，差異只在個人參與質量與活躍度
> - **Student Overview** 才能看到自己在不同專案的階段進展對比

### CARE-LAD 分析層次框架

| 層次 | 描述 | 範例 |
|------|------|------|
| **描述性** | 發生了什麼？ | 活動紀錄、次數統計 |
| **診斷性** | 為什麼發生？ | 模式分析、趨勢比較 |
| **預測性** | 未來會如何？ | 風險模型、軌跡預測 |
| **處方性** | 應該做什麼？ | 可操作建議、行動引導 |

> **研究核心警示（2025 MOOC RCT，n=8,745）：** 純數據儀表板對學習效果無顯著幫助；必須搭配可操作建議（處方性層次）才能提升學習動機與持續率。

## 第一部分：學生總覽（StudentOverview）

**定位：** 學生的個人學習歷程全景。**跨所有專案聚合**，讓學生看到自己整體的學習軌跡。

**這裡適合顯示的資訊：**
- 跨專案的整體表現摘要
- 各專案的進度與階段對比（因為不同專案可能在不同階段）
- 個人在所有專案的累積成長軌跡

### 現有功能

| 功能 | 實作狀態 | CARE 層次 |
|------|----------|-----------|
| 參與專案數 | ✅ | 描述性 |
| 所有專案的平均進度（%） | ✅ | 描述性 |
| 跨專案總任務數 + 各狀態分布 | ✅ | 描述性 |
| 跨專案聊天互動次數 | ✅ | 描述性 |
| 跨專案想法節點數 | ✅ | 描述性 |
| AI 諮詢次數 | ✅ | 描述性 |
| 我的專案列表（含進度條、當前階段文字、成員） | ✅ | 描述性 |
| 各專案個別進度條 | ✅ | 描述性 |
| 跨專案最近活動 Feed（8 筆混合） | ✅ | 描述性 |
| 本週反思列表 | ✅ | 描述性 |
| 學習活躍度（高/待提升，僅看本週反思） | ✅ | 診斷性（簡易） |
| 總反思數統計 | ✅ | 描述性 |

### 缺口分析

#### 缺口 1：各專案的 SDL 階段位置未視覺化比較✅ 已實作（2026-03-25）

**實作內容：** 在 StudentOverview「我的專案」列表的每個專案卡新增 `SdlStageBadge` 元件，用顏色區分四個階段（定標藍/擇策青/監評琥珀/調節紫），並顯示子階段編號，取代原本的純文字「階段: 1-2」。

**現狀：** 專案列表只顯示「第X階段-子階段Y」的文字，無法一眼看出「我在不同專案各走到哪裡」。

**為何屬於 Overview：** 這裡才能比較不同專案的階段進展，student-dashboard 只看單一專案，看不出差異。

**研究依據：** DAPER 模型指出，SDL 學習者需要看到自己在整個學習旅程（跨多個任務/專案）的全景位置。

**建議：** 將專案列表加入 SDL 階段視覺標籤，例如：
```
專案 A  [定標 █░░░] 25%   ← 尚在初期
專案 B  [監評 ███░] 67%   ← 進展良好
專案 C  [調節 ████] 90%   ← 即將完成
```

#### 缺口 2：缺乏跨時間的個人成長軌跡

**現狀：** 只顯示當前快照（數字），無法讓學生看到自己的進步趨勢。

**為何屬於 Overview：** 跨時間的成長要看「我在所有專案的整體表現」，而非單一專案內的變化。

**研究依據：** SDT（自我決定理論）研究（2024）指出「能力感知（Competence）」是自主學習動力的核心，需要讓學生看到成長而非只看現狀。LAK23 研究也確認學生最需要「compare to past self」。

**建議：** 加入月度趨勢圖，顯示過去 3 個月的反思次數、任務完成率、AI 互動次數的變化折線。

#### 缺口 3：活躍度判斷過於粗糙

**現狀：** 只用「本週有無反思」判斷「高/待提升」，忽略其他維度。

**建議：** 綜合計算活躍度分數，涵蓋：反思頻率 + 任務完成率 + 想法節點 + AI 互動，並顯示「本週 vs 上週」各維度的趨勢箭頭。

#### 缺口 4：無跨專案的可操作建議

**現狀：** 純數據展示，沒有「下一步做什麼」的引導。

**研究依據：** 2025 MOOC RCT 明確指出這是最關鍵的缺口。

**建議：** 給出 1–2 條跨專案個人化提示，例如：
- 「你在專案 A 已超過 2 週沒有反思，建議本週補上」
- 「專案 B 有 3 個任務逾期未完成，需要關注」

## 第二部分：學生專案儀表板（StudentDashboard）

**定位：** 進入特定專案後的深度學習分析。**聚焦在單一專案內，該學生與隊友的表現對比。**

**這裡適合顯示的資訊：**
- 在這個專案內，這位學生的貢獻與表現
- 與同組隊友的活躍度對比（相同階段背景下的差異才有意義）
- 在這個專案的反思深度與學習行為模式
- 這個專案專屬的目標達成狀況

### 現有功能

| 功能 | 實作狀態 | CARE 層次 |
|------|----------|-----------|
| 團隊統計卡（AI互動、想法節點、看板任務、個人/團隊反思） | ✅ | 描述性 |
| 個人進度百分比 + 當前階段/子階段 | ✅ | 描述性 |
| 學習時數（總計 + 平均 Session） | ✅ | 描述性 |
| 任務統計（按 Kanban 欄位狀態） | ✅ | 描述性 |
| 最近 7 天活動時間軸（線性清單） | ✅ | 描述性 |
| 10 個學習目標 + 進度追蹤 | ✅ | 描述性/診斷性 |
| 隊友清單（個人進度、最後上線時間） | ✅ | 描述性 |
| 成就系統（銅/銀/金，5 種類型） | ✅ | 描述性 |
| Quick Stats（聊天、Q&A、AI 次數） | ✅ | 描述性 |
| 5Rs 結構化反思整合 | ✅ 有反思功能 | 描述性 |
| Session 心跳式學習時間追蹤 | ✅ | 描述性 |
| 成就排行榜（Rankings） | ✅（⚠️ 研究反對） | 描述性 |

### 缺口分析

#### 缺口 1：5Rs AI 分析結果未回饋到儀表板✅ 已實作（2026-03-25）

**實作內容：** 新增 `FiveRsRadarChart.jsx` 元件。從 `personalReflections[].content` JSON 中解析 `feedback.scores`，跨所有已分析反思取平均值，以 Recharts `RadarChart` 渲染。附帶維度分數長條、最強/待加強維度 callout。無 AI 分析資料時顯示引導說明。插入 StudentDashboard 左欄，位於學習軌跡與學習目標之間。

**現狀：** 5Rs AI 分析系統已產出每個 R 層次的分析結果，但儀表板只顯示「反思次數」，沒有顯示「反思深度」。

**為何屬於 Dashboard：** 5Rs 分析是針對「這個專案的反思」，與專案高度綁定，應在該專案的儀表板中呈現。

**研究依據：** 多篇文獻強調反思「質量」比「次數」更重要，結構化反思框架（如 5Rs）的分析結果視覺化，是 SDL 儀表板的高價值功能。

**建議：** 加入五個 R 層次的雷達圖（Radar Chart），顯示此學生在這個專案的各層次平均分數：
- Reporting（報告）
- Responding（回應）
- Relating（聯繫）
- Reasoning（推理）
- Reconstructing（重建）

#### 缺口 2：缺乏 SDL 階段感知的可操作建議✅ 已實作（2026-03-25）

**實作內容：** 新增 `StageSuggestions.jsx` 元件。Rule-based 引擎根據 `currentStage × currentSubStage × personalData` 生成最多 3 條建議：固定 1 條「當前子階段焦點說明」（帶具體任務描述），加最多 2 條依個人數據觸發的條件建議（未反思 / 任務積壓 / 未使用想法牆 / 未用 AI / 未與隊友互動）。每條 action 型建議附具體 AI 提問範例。顯示於 StudentDashboard 右側欄最頂部，可摺疊。

**未來升級方向（AI 個人化版）：**

目前 rule-based 版本的建議對所有學生都是相同的文字模板。若要達到真正個人化，可新增後端端點 `POST /api/llm/stage-suggestions`，接收以下資料後呼叫 Gemini 生成：

```
{
  stage, subStage, stageName, subStageName,
  weeklyReflections, pendingTasks, totalTasks,
  ideaNodes, aiInteractions, chatMessages,
  recentTaskTitles   // 讓 AI 能針對具體任務給建議
}
```

Prompt 設計方向：
```
你是一個 SDL 學習教練。
學生目前在「{stageName}・{subStageName}」階段。
本週反思數：{n}，待辦任務：{pending}/{total}，
最近停滯的任務：「{taskTitle}」。
請給出 2 條具體、可立即行動的學習建議，語氣鼓勵。
```

這樣 AI 就能說出「你的任務『分析問卷結果』已停滯 4 天，建議先用樞紐分析表處理原始資料」這類真正個人化的建議，而非通用模板。前端只需在 `StageSuggestions.jsx` 加一個「重新生成」按鈕觸發此 API，其餘 UI 不變。

**現狀：** 顯示了當前階段，但沒有根據階段提供對應建議。

**為何屬於 Dashboard：** 建議必須結合「這個專案當前的 stage + 個人表現」才有意義，cross-project 的 overview 無法做到這個粒度。

**研究依據：** SDL 情境研究（RPTEL, 2021；ETR&D, 2025）指出，階段感知回饋能顯著提升自我調節學習行為。處於「監評」階段的學生需要不同於「擇策」階段的建議。

**建議：** 在 Dashboard 加入一個「本週學習建議」區塊，根據當前 stage + sub-stage + 個人數據自動生成，例如：
```
📌 你目前在「監評」階段 — 進行嘗試性研究
   本週任務完成率比上週下降 30%，
   建議檢視是否有卡關的任務需要求助。
```

#### 缺口 3：活動記錄缺乏節律可視化

**現狀：** 最近 7 天的線性活動清單，無法識別學習習慣模式（如「是否習慣最後一刻趕工」）。

**為何屬於 Dashboard：** 這個專案內的學習節律，是與專案的 deadline 和任務週期高度相關的。

**研究依據：** 2024 Self-Regulation LAD 研究指出，學習節律熱圖能有效幫助學生識別並改善拖延行為。

**建議：** 加入 4 週活動熱圖（Heatmap），以顏色深淺顯示每天的活動強度，讓學生看到自己的學習規律。

#### 缺口 4：學生端排行榜問題（⚠️ 僅限學生端）

**現狀：** 成就系統中有公開排名視圖（Rankings），學生可以看到自己與隊友的排名比較。

**為何只有學生端是問題：** 研究反對的是「對學習者展示競爭排名」這件事本身。教師端雖然也有活動排序列表，但那是教師用來識別誰需要關注的**管理工具**，不對學生公開，不產生社會比較壓力，兩者本質不同：

| 情境 | 問題程度 | 說明 |
|------|----------|------|
| 學生看到自己vs隊友排名 | ⚠️ 應修正 | 造成焦慮、打擊落後學生動機 |
| 教師看到學生活動排序 | ✅ 合理保留 | 管理工具，協助找出需要關注的學生 |

**研究依據：** SoLAR Handbook 明確將「對學習者展示排行榜」列為「避免」。研究一致指出，在非競技學習情境中，公開排名對落後學生有強烈打擊效果，提升焦慮、降低學習動機。

**建議（僅學生端）：** 移除與他人比較的排名視圖，改為「個人成就里程碑」：顯示自己在各成就類型的歷史進展（Bronze → Silver → Gold 的個人旅程），不顯示與他人的相對排名。

**教師端的活動排序（Teacher Dashboard）：** 保留，但建議將標題從「排行榜」改為「學生活動概況」，去除競爭意涵，明確定位為教師的管理參考工具。

#### 缺口 5：學生看不到自己的求助行為品質（Help-Seeking 不對稱）

**現狀：** 求助行為分析（品質分數、逃避風險）**只存在於 Teacher Dashboard**，學生完全看不到自己的求助模式。

**為何這是不對稱問題：**
- 教師端：「哪些學生有求助逃避風險？」→ 管理視角，識別需介入的學生
- 學生端：**目前完全缺失**。學生不知道自己是否有求助品質問題，也不知道自己的求助是否有效

**研究依據：** SDL 研究強調「元認知覺察（Metacognitive Awareness）」是自主學習的核心，學生必須能看到自己的求助行為模式才能自我調整。把求助品質數據只給教師看，等於剝奪了學生的自我覺察機會。

**建議（學生專案儀表板）：** 在 Dashboard 加入個人求助行為摘要：
- 本月求助次數與品質分數
- 求助後問題是否解決的追蹤（有效性）
- 若偵測到逃避模式，給予鼓勵性提示：「你最近傾向獨自解決困難，試試看在聊天室提問看看？」

#### 缺口 6：學生端缺乏「個人自我風險提示」✅ 已實作（2026-03-25）

**實作內容：** 新增 `StudentSelfRiskAlert.jsx` 元件，從 `personalData` 推導三項訊號：(1) 5+ 天無活動、(2) 本週未反思、(3) 待辦任務積壓 ≥3 且佔比 >60%。以鼓勵性語氣呈現，每項訊號附具體建議行動，可摺疊、可「今天不看」關閉。插入 StudentDashboard 頁面標題下方。

**現狀：** 教師端有逃避風險偵測（高/中/低），但學生端**完全沒有任何「我自己可能有風險」的提示**。

**為何這是不對稱問題：**
- 教師看到：「學生 A 逃避風險高，需要介入」
- 學生 A 看到：什麼都沒有，不知道自己已被標記為高風險

**研究依據：** 早期預警系統研究（2020）指出，最有效的系統是「讓學生自己看到警訊」，而非只讓教師看到再去介入，前者能培養自我調節能力，後者只是被動救援。

**建議（學生專案儀表板）：** 若系統偵測到參與度下滑，主動在學生儀表板顯示柔性提示：
```
⚠️ 你已 8 天沒有在這個專案留下任何活動紀錄
   需要協助嗎？可以試試求助隊友或 AI 助手。
```
注意語氣：是鼓勵性的提示，不是指責式的警告。

#### 缺口 7：學生看不到任何班級情境脈絡（匿名平均值）✅ 已實作（2026-03-25）

**實作內容：** 新增 `ClassAverageComparison.jsx` 元件。純前端計算（不需新 API）：想法節點平均 = `ideaNodes.length / teamMembers.length`；看板任務平均 = `kanbanTasks.length / teamMembers.length`；週反思平均 = 最近 7 天反思數 / 成員數（若 personalReflections 含多名用戶資料則顯示，否則顯示「暫無資料」）。三項指標各顯示「班平均 vs 我的」，以鼓勵性色彩標示高於/接近/低於平均（不用紅色）。插入 StudentDashboard 左欄底部，可摺疊。附說明文字：「不顯示個人排名，不影響評分」。

**現狀：** 學生只看到自己的數字，完全不知道「這樣算好還是不好？」

**為何這與排行榜問題不同：**
- 排行榜（已移除）：「你排第 3 名」→ 競爭性比較，研究反對
- 匿名班級平均：「班級平均本週反思 3 篇，你有 1 篇」→ 提供情境脈絡，不揭示個人排名

研究明確區分這兩者：匿名班級平均是「情境參照（Reference Frame）」，幫助學生判斷自己的狀態，而非競爭。

**研究依據：** SDT 研究（2024）指出，Competence 感知需要參照點，但參照點應是「班級匿名平均」或「過去的自己」，而非個人排名。

**建議（學生專案儀表板，需設計為可選擇開關）：**
```
本班本週平均   你的本週數據
反思  3.2 篇  ←  你: 1 篇  ↓ 低於平均
任務  5.8 個  ←  你: 7 個  ✅ 高於平均
想法  2.1 個  ←  你: 2 個  ≈ 接近平均
```

**定位：** 教師看到所有指導專案的整體狀況。**跨多個不同專案比較**，提供巨觀的教學視角。

- 不同專案之間的進度與健康度比較

### 缺口分析

#### 缺口 1：缺乏各專案 SDL 階段分布視覺化（最高優先）✅ 已實作（2026-03-25）

**實作內容：** 在 overview 視圖頂部加入 SDL 四階段橫向長條圖，以色彩區分定標/擇策/監評/調節，顯示各階段組數與百分比，並自動標示最多組所在的「本週重點關注」階段。

**現狀：** 專案列表只顯示進度百分比，沒有顯示各專案目前在哪個 SDL 階段。

**為何屬於 Overview（不是 Dashboard）：** 每個專案有自己的 stage，只有在 Teacher Overview 的跨專案視圖才能看到「哪些組在哪個階段」，這才有比較意義。在單一專案的 Teacher Dashboard 裡，所有學生都在同一個 stage，沒有分布可言。

**研究依據：** SDL 情境研究指出，教師最需要的跨班視圖是「我指導的各組，目前分布在學習旅程的哪個位置」，以便決定優先投入哪個組的輔導資源。

**建議：** 在 Teacher Overview 加入 SDL 階段分布圖：
```
定標  ■■              2 組 (20%)
擇策  ■■■■■           5 組 (50%)  ← 最多組在此，本週重點關注
監評  ■■■             3 組 (30%)
調節  □               0 組  (0%)
```

#### 缺口 2：需關注學生只顯示「數量」，看不到「是誰」✅ 已實作（2026-03-25）

**實作內容：** 「需要關注」面板重構為具名清單，每列顯示學生姓名、所屬專案、風險原因（進度 %）、以及「前往查看」按鈕連結至對應的 Teacher Dashboard。

**現狀：** 顯示「需關注學生 3 人」但不知道是哪個專案的誰。

**為何屬於 Overview：** 教師需要在跨所有專案中，優先找到最需要介入的學生，Overview 是觸發教師行動的入口。

**研究依據：** 早期預警系統研究（2020）指出，有效的預警系統必須能讓教師「立刻知道去找誰」，而非只提供計數。

**建議：** 將需關注學生展開為清單，顯示：學生姓名 + 所屬專案 + 風險原因，並加入「前往查看」按鈕連結到對應的 Teacher Dashboard。

#### 缺口 3：風險判斷只用單一維度（進度 < 30%）

**現狀：** 以單一進度百分比判斷，無法識別「進度看起來正常但已停止參與」的隱藏風險。

**研究依據：** 多篇早期預警研究建議至少結合：進度趨勢 + 最後活動時間 + 反思頻率三個維度。

**建議：** 加入「最後活動時間」作為第二判斷維度，例如「進度 60% 但 10 天無活動」的學生應被標記。

#### 缺口 4：各專案健康度缺乏橫向比較

**現狀：** 各專案只是條列式清單，無法快速判斷哪個專案狀況較差。

**建議：** 加入各專案的健康度評分卡（活躍度 + 反思品質 + 任務完成率的綜合分數），以顏色標示（綠/黃/紅），讓教師一眼看出哪個組需要優先關注。

### 缺口分析

#### 缺口 1：圖表與指標缺乏說明（資料識讀輔助）✅ 已實作（2026-03-25）

**實作內容：** 在 `StatsCards.jsx` 的每個統計卡標題旁加入 `?` Tooltip 圖示，hover 顯示指標定義、計算方式與健康參考值。五張卡片（總學生數、平均進度、反思記錄、想法節點、使用時長）均已加入說明。

**現狀：** 所有數字直接呈現，沒有說明「這個數字好不好？代表什麼？」

**為何屬於 Dashboard：** 教師在看單一班級的數據時，需要知道「班平均 vs 健康參考值」，這是 project-level 的情境判斷。

**研究依據：** CADA 研究（2022）明確指出，教師的資料識讀能力差異很大，缺乏輔助說明的儀表板常被誤讀，導致錯誤的教學決策。

**建議：** 為每個統計卡加入 `?` tooltip，說明：
- 指標的計算方式
- 參考的健康值範圍
- 例：「協作分數 72 — 低於 50 需關注，高於 80 表現優異 ✅」

#### 缺口 2：無教師介入紀錄（Intervention History）

**現狀：** 教師可以查看學生狀態，但沒有地方記錄「我已對這個學生做了什麼、效果如何」。

**為何屬於 Dashboard：** 介入行動是針對「這個專案裡的特定學生」，是 project-level 的師生互動記錄。

**研究依據：** SoLAR Handbook 指出介入歷史對後續教學改進至關重要，也能防止重複打擾同一學生。

**建議：** 在個別學生視圖加入「教師備忘」功能，記錄觀察與行動，讓 AI 分析報告也能參考介入歷史。

#### 缺口 3：5Rs 反思質量未整合到學生個別視圖

**現狀：** AI 生成的 5Rs 分析結果沒有彙整到教師端的學生個別視圖。

**為何屬於 Dashboard：** 教師查看個別學生時，應能看到「這個學生的反思深度如何隨時間變化」，這是在這個專案脈絡下的學生成長追蹤。

**研究依據：** 文獻強調「成長軌跡」比「當前狀態」更能反映真實學習。

**建議：** 在個別學生視圖加入「反思深度趨勢折線圖」，y 軸為 5Rs 綜合分數，x 軸為時間，讓教師看到學生是否在進步。

#### 缺口 4：學習節律分析缺失

**現狀：** 有活動 Feed，但無法識別全班或個別學生的學習時間模式。

**為何屬於 Dashboard：** 「這個班的學生什麼時候最活躍？是否有最後一刻趕工的模式？」是 project-level 的班級行為分析。

**建議：** 在 Analytics 視圖加入全班學習節律熱圖（以星期幾 × 時段為軸），讓教師看到班級整體的活動時間分布，識別是否有集中在 deadline 前才衝刺的模式。

#### 缺口 5：本週 vs 上週班級指標趨勢（Teacher Dashboard 也需要）✅ 已實作（2026-03-25）

**實作內容：** 在 `useMetricsData.js` 的 `classStats` 計算中新增 `weekTrend` 物件，以週一為邊界切分本週/上週的日期區間，從已載入的 `reflections` 陣列和 `nodes` 陣列做日期篩選，計算三個趨勢差值：`totalReflections`（本週 vs 上週反思篇數）、`totalIdeaNodes`（本週 vs 上週新增節點數）、`activeStudents`（本週有活動 vs 上週有活動的學生數）。在 `StatsCards.jsx` 新增 `TrendBadge` 元件（上升綠色 ↑ / 下降紅色 ↓ / 持平灰色 —），顯示於對應統計卡的 subtitle 旁。`averageProgress` 和 `totalUsageHours` 因無日期分段歷史資料，不顯示趨勢（trend: null）。**完全純前端實作，不需要任何後端改動。**

**現狀：** 統計卡只顯示當前數值快照，教師無法判斷「班級整體是在進步還是退步」。

**為何這與學生端的趨勢需求不同：**
- 學生端（Student Dashboard）：「我個人有沒有進步？」→ 自我調節動機
- 教師端（Teacher Dashboard）：「我的教學介入有沒有效果？班級整體是否在改善？」→ 教學決策依據

**研究依據：** CADA 研究（2022）指出，教師需要看到「介入前 vs 介入後」的班級數據變化，才能判斷教學策略是否有效。

**建議：** 在統計卡旁加入週趨勢箭頭與差值：
```
本週反思數  47 篇  ↑ 比上週 +12 篇  (上週 35 篇)
不活躍學生   3 人  ↓ 比上週 -1 人   (上週 4 人)  ← 介入有效
```

#### 缺口 6：學習目標達成率（全班視角）

**為何屬於 Teacher Dashboard：** 教師需要知道「全班在哪些目標上普遍達不到」，這是課程設計層面的洞察，個別學生視角看不出來。

**與學生端的不同：**
- 學生端：「我自己的 10 個目標達成了幾個？」

**建議：** 在 Analytics 視圖加入目標達成率總覽：

#### 缺口 7：全班 5Rs 維度聚合（教師端獨有需求）✅ 已實作（2026-03-25）

**實作內容：** 新增 `ClassFiveRsRadarChart.jsx` 元件。複用學生端 `FiveRsRadarChart.jsx` 的 Recharts 雷達圖架構，改接 `reflections`（全班所有反思）。使用 `parse5RsContent` 解析每篇反思的 `feedback.scores`，對五個維度分別取全班平均（依篇數加權而非依人數），顯示紫色雷達圖（區別於學生端的青色）。副標題顯示「X 篇已分析（Y 位學生）」，底部 callout 標示「全班最強維度」與「建議加強教學」維度，引導教師決策。插入 AnalyticsView 在反思長條圖之後。
